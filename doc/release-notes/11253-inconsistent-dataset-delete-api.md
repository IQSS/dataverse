## Bug Fix
The behavior of the DELETE "/api/datasets/{id}" endpoint has changed. For superusers, usly, it would delete a dataset that had only a draft version for normal users, and for superusers, it would escalate to a "destroy" action even if the dataset had published versions. Now, the call will only succeed if the dataset has only a draft version and has never been published. If the dataset has more than one version (e.g., a draft and a released version), it will no longer delete the draft but will instead return an 'unauthorized' response. For superusers, the call will no longer be 'upgraded' to a dataset destroy action and will instead suggest using the /destroy endpoint to delete the published version.
