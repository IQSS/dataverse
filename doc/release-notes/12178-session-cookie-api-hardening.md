A new feature flag, `dataverse.feature.api-session-auth-hardening`, adds a same-site check to API requests authenticated with a logged-in session (the JSESSIONID cookie). When enabled, the browser must prove the request originated from the same site configured in `dataverse.siteUrl` -- using the `Origin` and `Referer` headers that browsers set automatically and that page scripts cannot forge.

One intent of this hardening flag is to make production use of front-end code, such as React components embedded in the JSF pages or other apps deployed on the Dataverse site, practical without requiring API keys, signed URLs, or other authentication mechanisms. For this, the flag should be enabled together with `dataverse.feature.api-session-auth` flag. Previously, `api-session-auth` was recommended only for testing because, even with the recommended `SameSite:Lax` cookie setting, some cross-site request forgery (CSRF) attacks were possible. The new flag blocks these. The new flag can also be used on its own to harden the Access API (used for file downloads) and block, for example, bookmarks and download links on other sites for restricted files.

See [the guides](https://guides.dataverse.org/en/latest/installation/config.html#dataverse-feature-api-session-auth-hardening) for configuration details.
