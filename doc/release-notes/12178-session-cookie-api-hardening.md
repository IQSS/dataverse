A new feature flag, `dataverse.feature.api-session-auth-hardening`, adds cross-site request forgery (CSRF) protection to API requests authenticated via session cookie (JSESSIONID): the request must come from the same origin as `dataverse.siteUrl`, checked through the browser-set `Origin` and `Referer` headers. It can be enabled on its own to harden the Access API, or together with `dataverse.feature.api-session-auth`.

With the flag enabled, a session-cookie request carrying neither header is treated as a guest request. A restricted file therefore no longer downloads from a bookmarked or shared link, even while logged in, but still does from links on the site itself. See [the guides](https://guides.dataverse.org/en/latest/installation/config.html#dataverse-feature-api-session-auth-hardening) for details.
