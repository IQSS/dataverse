### URL signing fixed and hardened

Signed URLs now work for URLs containing special characters (broken in 6.10, e.g. for `doi:` persistent identifiers), and no longer require configuration: when the `dataverse.api.signing-secret` JVM option is not set, a strong signing secret is generated automatically at startup and kept only in memory - it is never stored anywhere. With a generated secret, signed URLs do not survive a server restart, and on a multi-server installation each server signs with its own secret; installations that need either - or that want signed URLs issued before an upgrade or restart to stay valid - should set `dataverse.api.signing-secret` (minimum 36 characters, shorter values are ignored with a warning). See [dataverse.api.signing-secret](https://guides.dataverse.org/en/latest/installation/config.html#dataverse-api-signing-secret) in the Configuration Guide.
